# OBS-Detect Project Rules & Knowledge Base

이 파일은 obs-detect 프로젝트의 구조, 설계 방향 및 특이사항을 기록한 문서입니다. 에이전트(AI)는 이 프로젝트에서 작업할 때 항상 아래의 내용을 숙지하고 준수해야 합니다.

## 1. 렌더링 및 비동기(Async) 구조 (중요)
* **목표 프레임률 방어**: OBS의 렌더링 파이프라인(60FPS)이 인퍼런스 지연으로 인해 끊기는 현상을 막기 위해, 모델 인퍼런스는 백그라운드 스레드(`inference_thread_loop`)에서 비동기로 처리됩니다.
* **텍스처 복사 최적화**: 렌더링 스레드(`detect_filter_video_render`)에서는 GPU 상에서 렌더링을 유지하기 위해 CPU-GPU 간 메모리 복사(`cv::Mat` 클론)를 최소화하고, `gs_texrender_get_texture(tf->texrender)`를 사용하여 베이스 프레임을 가져옵니다.
* **지연 제어 및 딜레이 싱크**:
  * **VideoDelayFrames (최대 10프레임)**: 마스크가 비디오 속 객체보다 몇 프레임 **앞서서** 나타날지를 조절하는 **마스크 선행 타이밍 미세 조정 슬라이더**입니다. 0으로 설정하면 마스크가 비디오 객체와 완벽하게 동일한 시점에 렌더링됩니다. 값을 높일수록 마스크가 비디오보다 해당 프레임 수만큼 더 앞선 시점의 데이터를 조회하여 객체보다 먼저 덮이게 됩니다.
    * **주의**: 이 슬라이더는 모델 추론 지연(약 3프레임) 보정을 목적으로 설계되었으나, Look-ahead Delay(0.5초)가 이미 모델 지연을 완전히 흡수하기 때문에 D=0에서도 항상 싱크가 완벽하게 맞습니다. 사실상 선제 마스킹 선행 타이밍을 미세 조정하는 도구로 사용됩니다.
  * **Look-ahead Delay (0.5초 고정, FPS 연동)**: 객체 추적의 시간적 여유를 확보하기 위한 기능입니다. 비디오를 0.5초 분량의 프레임 수(`round(0.5 * FPS)`)만큼 지연 버퍼링함으로써, 실시간으로 처리된 미래의 감지 데이터를 대조하여 객체가 실제 나타나기 0.25초(`round(0.25 * FPS)`) 전부터 미리 마스크를 씌우는 **선제 마스킹(Reverse Masking)**을 가능케 합니다. 이 0.5초 버퍼가 모델 인퍼런스 지연(약 3프레임)을 완전히 흡수하므로, 어떤 사양의 컴퓨터에서도 Look-ahead가 활성화된 이상 모델 지연에 의한 마스크 밀림 현상은 발생하지 않습니다.
  * **싱크 오프셋 조절 메커니즘 (중요)**:
    * 비디오는 `VideoDelayFrames(D) + Look-ahead Delay` 만큼 지연하여 렌더링하지만, 마스크를 그릴 때 조회하는 프레임 ID(`maskRenderFrameId`)는 지연 큐의 인덱스 `[D]` 위치를 사용합니다.
    * 큐는 `front()=가장 오래된 과거`, `back()=가장 최신` 순서로 정렬되므로, 인덱스 `[D]`는 비디오(front)보다 **D프레임 더 최신(미래) 방향**의 데이터입니다.
    * 따라서 D를 높이면 비디오는 D프레임 더 과거를 보여주고, 마스크는 D프레임 더 미래 데이터를 조회하게 되어 마스크가 객체보다 앞서서 덮이는 효과가 커집니다.
    * D=0일 때 `maskRenderFrameId = delayedFrameIds[0] = front()` 즉 비디오와 완전히 동일한 시점을 가리켜 싱크가 완벽하게 맞습니다.


## 2. 트래킹 및 마스킹 기능
* **마스킹 동적 확장 (Dynamic Expansion)**: 마스크 확장 기능은 단순히 `cv::dilate`를 쓰지 않고, 대상 객체의 화면 내 크기 비율에 맞춰 동적으로 확장(Scale)하도록 직접 `cv::rectangle` 수학 연산으로 구현되어 있어 성능 부하가 거의 없습니다.
* **SORT 기반 대상 고정 및 예외 처리**: 대상이 잠시 사라지더라도 유지하는 유령 방지(Min Hit Frames), 제외 대기 시간(Exclude Delay), 제외 해제 면적 완화 비율(Safety Drop-off Ratio), 단일 대상일 때만 제외(Exclude Single Only) 등의 커스텀 옵션 로직이 구현되어 있습니다.

## 3. 하드웨어 및 빌드 환경
* **하드웨어 가속**: CUDA는 환경 호환성 문제로 기본 옵션에서 제외되었으며, 현재는 **CPU** 및 **GPU (DirectML)** 최적화를 위주로 동작합니다.
* **빌드 시스템**: CMake를 기반으로 하며, 빌드 명령어는 `cmake --build build --config Release` 형식을 따릅니다.
* **디버그 모드**: `Debug Mode`를 켜면 현재의 인퍼런스 레이턴시와 FPS를 OBS 화면에 텍스트로 출력합니다.

## 4. 로컬라이제이션 (언어팩)
* UI 프로퍼티를 추가할 경우, 반드시 `data/locale/en-US.ini` 및 `data/locale/ko-KR.ini` 두 파일 모두에 번역을 추가해야 합니다.

## 5. 릴리즈 및 설치 패키지 배포
* **GitHub Actions 자동화**: 본 프로젝트는 공식 OBS 플러그인 템플릿의 빌드 스크립트를 내장하고 있어 `.github/workflows`를 통한 자동화된 CI/CD 배포를 지원합니다.
* **로컬 Windows 빌드**: 만약 사용자(개발자)의 로컬 윈도우 환경에서 수동으로 `.exe` 인스톨러를 제작해야 한다면, CPack 대신 `build/` 디렉터리에 생성된 `installer-Windows.generated.iss` 파일을 **Inno Setup (iscc.exe)** 프로그램을 통해 직접 컴파일해야 합니다.

* 코드 주석은 항상 영어로 작성합니다.
