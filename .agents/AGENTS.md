# OBS-Detect Project Rules & Knowledge Base

이 파일은 obs-detect 프로젝트의 구조, 설계 방향 및 특이사항을 기록한 문서입니다. 에이전트(AI)는 이 프로젝트에서 작업할 때 항상 아래의 내용을 숙지하고 준수해야 합니다.

## 1. 렌더링 및 비동기(Async) 구조 (중요)
* **목표 프레임률 방어**: OBS의 렌더링 파이프라인(60FPS)이 인퍼런스 지연으로 인해 끊기는 현상을 막기 위해, 모델 인퍼런스는 백그라운드 스레드(`inference_thread_loop`)에서 비동기로 처리됩니다.
* **텍스처 복사 최적화**: 렌더링 스레드(`detect_filter_video_render`)에서는 GPU 상에서 렌더링을 유지하기 위해 CPU-GPU 간 메모리 복사(`cv::Mat` 클론)를 최소화하고, `gs_texrender_get_texture(tf->texrender)`를 사용하여 베이스 프레임을 가져옵니다.
* **동기화 모드 (Zero-Delay)**: 고사양 PC 사용자를 위해 렌더링 프레임 틱에서 직접 인퍼런스를 수행하는 동기화 모드(`tf->syncMode`) 기능이 존재합니다. 이는 1~2프레임의 지연을 완벽하게 제거하지만, 렌더링 틱을 차단하므로 사양이 부족하면 전체 OBS 프레임 드랍을 유발할 수 있습니다.
* **지연 제어 및 딜레이 싱크**:
  * **VideoDelayFrames (최대 10프레임)**: 모델의 물리적 인퍼런스 지연(약 3프레임 내외)으로 인해 마스크가 객체보다 늦게 따라가는 현상을 보정하기 위해 도입되었습니다. 비디오 렌더링 시점을 인위적으로 몇 프레임 늦춤으로써, 이미 인퍼런스가 완료된 시점의 정확한 객체 위치 데이터가 마스크로 씌워지도록 동기화합니다.
  * **Look-ahead Delay (0.5초 고정, FPS 연동)**: 객체 추적의 시간적 여유를 확보하기 위한 기능입니다. 비디오를 0.5초 분량의 프레임 수(`round(0.5 * FPS)`)만큼 지연 버퍼링함으로써, 실시간으로 처리된 미래의 감지 데이터를 대조하여 객체가 실제 나타나기 0.25초(`round(0.25 * FPS)`) 전부터 미리 마스크를 씌우는 **선제 마스킹(Reverse Masking)**을 가능케 합니다.
  * **싱크 오프셋 조절 메커니즘 (중요)**:
    * 비디오와 마스크가 항상 동일하게 늦어지면 상대적인 싱크 조절이 되지 않고 전체 스트림 지연만 늘어납니다.
    * 이를 방지하기 위해 비디오는 `VideoDelayFrames + Look-ahead Delay` 만큼 지연하여 렌더링하지만, 마스크를 그릴 때 조회하는 프레임 ID(`maskRenderFrameId`)는 비디오 지연값(`VideoDelayFrames`)을 제외한 `Look-ahead Delay` 시점만을 기준으로 데이터를 획득합니다.
    * 이로 인해 슬라이더를 통해 `VideoDelayFrames`를 $D$로 늘리면 비디오만 $D$프레임 추가 지연되어 마스크가 비디오보다 상대적으로 $D$프레임 미래의 시점을 보게 되며, 모델의 3프레임 연산 지연을 마스크와 비디오의 시점 오프셋 차이로 보상(상쇄)하여 완벽하게 밀착하는 최적의 보정 포인트를 조절할 수 있습니다.



## 2. 트래킹 및 마스킹 기능
* **마스킹 동적 확장 (Dynamic Expansion)**: 마스크 확장 기능은 단순히 `cv::dilate`를 쓰지 않고, 대상 객체의 화면 내 크기 비율에 맞춰 동적으로 확장(Scale)하도록 직접 `cv::rectangle` 수학 연산으로 구현되어 있어 성능 부하가 거의 없습니다.
* **SORT 기반 대상 고정 및 예외 처리**: 대상이 잠시 사라지더라도 유지하는 유령 방지(Min Hit Frames), 제외 대기 시간(Exclude Delay), 제외 해제 면적 완화 비율(Safety Drop-off Ratio), 단일 대상일 때만 제외(Exclude Single Only) 등의 커스텀 옵션 로직이 구현되어 있습니다.

## 3. 하드웨어 및 빌드 환경
* **하드웨어 가속**: CUDA는 환경 호환성 문제로 기본 옵션에서 제외되었으며, 현재는 **CPU** 및 **GPU (DirectML)** 최적화를 위주로 동작합니다.
* **빌드 시스템**: CMake를 기반으로 하며, 빌드 명령어는 `cmake --build build --config Release` 형식을 따릅니다.
* **디버그 모드**: `Debug Mode`를 켜면 현재의 인퍼런스 레이턴시와 FPS를 OBS 화면에 텍스트로 출력합니다.

## 4. 로컬라이제이션 (언어팩)
* UI 프로퍼티를 추가할 경우, 반드시 `data/locale/en-US.ini` 및 `data/locale/ko-KR.ini` 두 파일 모두에 번역을 추가해야 합니다.

## 5. 릴리즈 및 설치 패키지 배포
* **GitHub Actions 자동화**: 본 프로젝트는 공식 OBS 플러그인 템플릿의 빌드 스크립트를 내장하고 있어 `.github/workflows`를 통한 자동화된 CI/CD 배포를 지원합니다.
* **로컬 Windows 빌드**: 만약 사용자(개발자)의 로컬 윈도우 환경에서 수동으로 `.exe` 인스톨러를 제작해야 한다면, CPack 대신 `build/` 디렉터리에 생성된 `installer-Windows.generated.iss` 파일을 **Inno Setup (iscc.exe)** 프로그램을 통해 직접 컴파일해야 합니다.

## 6. 프로젝트 현재 진행 상황 및 주요 마일스톤 (최신)
* **얼굴 인식(YuNet/SFace) 비동기 처리 완료**: 기존에 렌더링 틱을 차단하여 프레임 드랍을 유발하던 얼굴 인식 및 특징 추출 로직을 전용 백그라운드 스레드(`faceInferenceQueue`)로 완전히 분리하여 OBS 성능 저하 문제를 해결했습니다.
* **얼굴 특징 데이터 캐싱 및 최적화**: 설정 콜백(`detect_filter_update`)에서 불필요하게 모델을 재로드하는 문제를 수정하고, 참조 폴더 내 이미지 특징(`referenceFaceFeatures`)을 최초 1회만 계산하도록 최적화했습니다.
* **추적 제외 인원수 제한 기능(`maxExemptPersons`) 적용**: 여러 참조 이미지를 통해 인식률을 높이면서도, 화면에서 지정된 명수(기본 1명)의 타겟을 찾으면 그 즉시 얼굴 인식 연산을 완전히 멈추도록 하여 CPU 성능 낭비와 제3자 오인식(False Positive) 가능성을 원천 차단했습니다.
